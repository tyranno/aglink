# 텔레그램에서 VS Code 의 Claude 세션에 붙어 대화하기

**날짜:** 2026-09-18
**대상:** `aglink/host` (텔레그램 봇). 원격 리눅스에 설치할 것은 없다.

## 문제

작업 대부분이 VS Code 를 SSH 원격으로 열어 진행된다. 그 안에서 도는 Claude
세션이 지금 무엇을 하는지 보거나 한마디 시키려면, 지금은 셋 중 하나를 해야 한다.

1. 그 화면을 캡처한다 — 비전 토큰이 들고, 스크롤 밖은 못 본다.
2. UIA 접근성 트리를 읽는다 — 텍스트로 읽히지만 **포그라운드 창**만 읽히고,
   채팅 입력칸에 포커스가 없으면 타이핑이 조용히 흘러간다. 실제로 이 세션에서
   두 번, 보낸 줄 알았던 메시지가 전달되지 않았다.
3. 자리에 앉아서 직접 친다.

셋 다 "내 자리 앞"을 전제한다. 텔레그램으로 움직이는 이 봇의 이점이 사라진다.

## 목표

- 텔레그램에서 **어떤 세션이 살아 있는지** 확인한다. 이름을 몰라도 고를 수 있다.
- 그중 하나에 **붙어서**, 그 뒤로는 평문을 치면 그 세션에 전달된다.
- 세션이 답을 내면 **한 번** 받는다. 붙잡고 폴링하지 않는다.
- 설정은 평문으로 된다. `!` 명령을 외우지 않아도 된다.

## 비목표

- 세션을 새로 띄우거나 죽이는 것. 붙는 것만 한다.
- 여러 세션에 동시에 붙는 것. 대화 하나에 세션 하나.
- 화면 캡처를 대체하는 것. 이 경로는 텍스트만 다룬다. 화면이 필요하면
  `!screen` 이 그대로 있다.
- 파일 편집·승인 프롬프트 응답. 승인 대기는 감지해서 알리되, 누르지는 않는다.

## 실측한 것

설계의 전제를 전부 원격 한 대에서 직접 재 봤다. 아래는 추정이 아니라 관측이다.

### 목록은 Claude CLI 가 공식으로 준다

원격에서 일회용 `claude -p` 를 띄워 `ListAgents` 를 부르면 그 머신의 다른
세션이 그대로 나온다.

```
$ claude -p --safe-mode --allowedTools ListAgents \
    "Call ListAgents once and print its raw output verbatim."

Peer sessions (2):
  proj-a-cf [875607]  ·  interactive  ·  idle  ·  started 1h ago
  proj-b-4f [2265ec]  ·  interactive  ·  busy  ·  tmux sv:@0.%0  ·  started 1h ago
```

여기서 **이름 · 참조 · 대화형 여부 · busy/idle · 가동시간**이 한꺼번에 나온다.
`busy/idle` 은 JSONL 을 긁어서는 얻을 수 없는 값이다. 세션 이름은 작업 디렉터리
이름에서 자동으로 만들어지고, 사용자가 `claude -n <이름>` 으로 직접 붙일 수도
있다.

### 쓰기는 `SendMessage` 가 **그대로** 넣는다

```json
{"success":true,"message":"… → proj-a-cf (another Claude session on this machine)",
 "msg_id":"7a69c76a-9020-4b5f-be49-85b5f14cbf67"}
```

받는 쪽 기록을 열어 확인한 결과, 보낸 한국어 문장이 **한 글자도 바뀌지 않고**
도착했다. 도구가 돌려주는 요약 한 줄만 영어로 의역될 뿐 본문은 원문이다.

받는 쪽에는 이렇게 보인다.

```
<cross-session-message from="uds:/run/user/<uid>/cc-socks/<pid>.sock"
                       from-name="proj-b-4f" …>
  …본문…
</cross-session-message>

This came from another Claude session — not <사용자>.
```

마지막 줄이 중요하다. **받는 세션은 이걸 사람 말이 아니라 옆 세션 말로 취급한다.**
사람의 지시와 같은 무게로 받게 하려면 본문에 그렇게 적어 주어야 한다.

대상이 일하는 중이면 `"reason":"absorbed_mid_turn"` 으로 기록된다 — 버려지지
않고 진행 중인 턴에 흡수된다. 새 턴을 시작시키지는 못한다.

### 답은 돌아오지 않는다

`SendMessage` 는 넣고 끝이다. 답은 **대상 세션 안에서** 나온다. 그래서 읽기는
기록 파일을 직접 본다.

```
~/.claude/projects/<작업디렉터리를 대시로 인코딩한 이름>/<uuid>.jsonl
```

관측된 파일 크기는 **33 MB**. `tail -c` 로만 읽는다. 전체를 읽으면 안 된다.
uuid 는 대개 프로세스 명령줄의 `--resume=<uuid>` 에 그대로 있고, 없으면 그
디렉터리에서 가장 최근 파일이다.

### 계정 경계가 곧 한계다

세션 소켓은 `/run/user/<uid>/cc-socks/<pid>.sock` 에 **0600** 으로 있다.
다른 계정 것은 보이지도 읽히지도 않는다. 그래서 **SSH 계정 하나는 그 계정이
띄운 세션만 다룬다.** 작업 디렉터리가 남의 홈 아래에 있어도 소유자는 세션을
띄운 계정이다 — 실제로 관측된 두 세션 중 하나가 그랬다.

두 계정을 다 쓰려면 등록된 SSH 호스트를 둘로 둔다. 목록에는 어느 등록
이름에서 나온 세션인지 함께 찍는다.

## 명령 표면

```
!sessions            붙을 수 있는 세션 목록
!attach <번호|이름>   붙기
!detach              풀기
!status              (기존) 끝에 붙어 있는 세션 한 줄 추가
(평문)               붙어 있으면 그 세션으로, 아니면 지금까지대로 워커로
```

`!sessions` 출력:

```
1. proj-a-cf     dev   1시간째 · 쉬는 중
   마지막: 2단계가 끝났습니다. 담기와 짓기를 지시했습니다.
2. proj-b-4f     dev   1시간째 · 일하는 중
   마지막: 템플릿-생성물 비교 시험을 뒤집는 중입니다.
```

이름 · 등록 호스트 · 가동시간 · busy/idle 은 `ListAgents` 에서, "마지막" 한 줄은
기록 파일 끝에서 가져온다. 번호는 이 목록 한 번에만 유효하다.

평문으로도 같은 일이 된다. 붙지 않은 상태에서 들어온 평문이 **세션을 고르는
말처럼 보이면**(`제어`, `붙어`, `연결` + 목록에 있는 이름) 그 세션에 붙고 한 줄로
알린다. 이름이 없으면 목록을 먼저 보여 준다.

## 동작

```
!sessions
  └ ssh <호스트> → claude -p --safe-mode --allowedTools ListAgents
  └ ssh <호스트> → 각 세션의 기록 파일 tail -c → 마지막 어시스턴트 한 줄
  └ 두 결과를 이름으로 합쳐 출력

!attach <이름>
  └ ListAgents 를 한 번 더 돌려 그 이름이 지금도 살아 있는지 확인한다
  └ 있으면 대화별 상태에 기록한다. 메시지는 보내지 않는다.

(붙은 상태에서 평문)
  └ ssh <호스트> → claude -p --allowedTools SendMessage
       본문 = 사용자가 친 그대로 + "이건 사용자가 텔레그램으로 보낸 말이다" 한 줄
  └ msg_id 를 받으면 기록 파일의 현재 끝 위치를 적어 둔다
  └ 그 위치 이후로 어시스턴트 출력이 멈춘 것이 확인되면 한 번 요약해서 보낸다
```

마지막 줄이 이 설계의 핵심이자 가장 약한 곳이다. "턴이 끝났다"를 기록 파일만
보고 판정해야 한다. **판정: 마지막 어시스턴트 기록 이후 일정 시간 새 기록이
없으면 끝난 것으로 본다**(기본 20초, 설정값). 오판하면 중간 상태를 한 번 더
보내는 것으로 끝나므로 손해가 작은 쪽으로 기운다. `ListAgents` 의 busy/idle 을
보조 신호로 함께 본다 — 둘 다 조용할 때만 끝으로 친다.

## 상태

붙어 있는 세션은 **대화별로, 메모리에만** 둔다. 호스트가 재시작하면 전부
풀린다. 풀린 줄 모르고 계속 치는 일을 막기 위해, 붙지 않은 상태에서 들어온
평문은 지금까지대로 워커로 가고 `!status` 에 항상 현재 붙은 세션이 보인다.

기록에 남기지 않는 이유는 단순하다. 원격 세션은 호스트보다 먼저 죽는 쪽이고,
살아 있지도 않은 이름에 붙어 있다고 적힌 상태가 더 나쁘다.

## 붙일 자리

- 명령 분기: `host/bot.go` 의 `handleCommand` — `!ssh` 옆에 나란히.
- 평문 가로채기: 진입점이 **둘**이다. `host/bot.go`(텔레그램)와
  `host/chatcontrol.go`(웹). 둘 다에서 같은 판정을 불러야 한다 — 한쪽만 고치면
  웹에서 친 말이 세션이 아니라 워커로 샌다.
- 원격 실행: `host/ssh.go` 의 `runSSH(ctx, cfg, hostName, remoteCmd)` 를 그대로
  쓴다. 새 SSH 코드는 필요 없다.
- 호스트 등록: 기존 `ssh.hosts` (name/host/port/user/password/key_file) 를
  그대로 쓴다. 이 기능 전용 설정은 "어느 등록 이름들을 뒤질지" 하나뿐이다.

## 위험과 처리

**세션 내용이 텔레그램으로 나간다.** 목록의 "마지막 한 줄"과 턴 요약은 그
세션이 다루던 것을 그대로 옮긴다. 오늘 이 세션에서 접속 자격이 적힌 파일이
화면에 떠 있다가 그대로 읽힌 일이 있었다. 처리: 목록의 한 줄은 **110자에서
자른다**. 요약도 길이 상한을 둔다. 전문을 보려면 명시적으로 한 번 더 요청하게
한다.

**중계가 LLM 이다.** 본문은 실측상 그대로 갔지만, 중간의 `claude -p` 가 언제든
의역할 수 있다. 처리: 본문을 프롬프트에 섞지 말고 파일로 넘겨 "이 파일 내용을
그대로 SendMessage 하라"로 지시한다. 보낸 뒤 기록에서 도착한 문장을 대조한다.

**받는 쪽이 사람 말로 안 본다.** `This came from another Claude session` 이
붙는다. 처리: 본문 첫 줄에 출처를 명시한다.

**일하는 중이면 흡수된다.** 새 턴이 시작되지 않는다. 처리: `ListAgents` 가
busy 면 보내기 전에 한 줄로 알린다. 보내는 것 자체는 막지 않는다 — 실측상
버려지지는 않는다.

**일회용 `claude -p` 가 토큰을 쓴다.** 목록 한 번, 보내기 한 번마다 원격 계정의
토큰이 든다. 처리: 읽기는 전부 `tail -c` 로 하고 LLM 을 태우지 않는다. LLM 은
`ListAgents` 와 `SendMessage` 두 군데서만 쓴다. `--safe-mode` 로 플러그인·훅을
끄고 최소로 띄운다.

**남의 계정 세션은 안 보인다.** 위 "계정 경계" 참고. 이건 막는 게 맞는 동작이라
우회하지 않는다. 등록 호스트를 늘려서 푼다.

## 시험

- `ListAgents` 출력 파싱 — 0개 / 1개 / 여러 개 / busy·idle 섞임 / 깨진 줄.
- 기록 파일 tail 파싱 — 잘린 첫 줄, 어시스턴트 출력이 없는 꼬리, 빈 파일.
- 붙기 판정 — 목록에 없는 이름, 번호 범위 밖, 목록을 본 적 없는 상태의 번호.
- 평문 갈림 — 붙은 상태/안 붙은 상태 × 텔레그램/웹 **네 경우 전부**.
- 길이 자르기 — 110자 경계에서 한글이 깨지지 않을 것.
- 턴 끝 판정 — 조용해졌다가 다시 쓰기 시작하는 경우 두 번 보고하지 않을 것.

원격이 필요한 시험은 `runSSH` 를 가짜로 바꿔서 돌린다. 실제 원격까지 가는
시험은 수동 한 번으로 족하다.

## 남은 것

- 승인 프롬프트가 떠서 세션이 멈춘 경우를 기록만 보고 알아낼 수 있는가.
  알아낼 수 있으면 "멈춰 있음"으로 보고한다. 누르지는 않는다.
- 세션이 도중에 죽으면 붙어 있는 쪽이 어떻게 아는가. 지금 설계는 다음 보내기가
  실패할 때 안다. 목록을 주기적으로 볼지는 정하지 않았다.
