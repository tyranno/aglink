# aglink 원격 제어 — 세션이 "VS Code를 돌리는 그 PC"를 제어하도록

2026-11-14 · 설계 문서 (구현 전 승인 대상)

## 의도 (왜)

여러 PC(집·회사 등)가 **같은 계정**으로 하나의 서버에 VS Code Remote-SSH로 접속해
`aglink-web-remote` / `aglink-screen-remote` 로 그 PC의 브라우저·화면을 제어한다.
voice(답변 읽어주기)는 Claude Code의 Stop 훅으로 동작한다.

지금은 각 PC의 aglink 데몬을 **고정 포트 reverse tunnel**(`ssh -R 48219/48220/48231`)로
서버에 내보낸다. 서버의 `~/.claude` MCP 등록도 **고정**(`http://127.0.0.1:48219/mcp`)이다.
→ **먼저 붙은 PC가 서버 포트를 독점**하고, 나중에 붙은 PC의 세션이 `aglink-web-remote`를
쓰면 **자기도 모르게 엉뚱한(먼저 붙은) PC를 조작**한다. voice 훅도 엉뚱한 PC로 가서
집 음성이 "답변 기다리는 중"에서 멈춘다. (2026-11 실제 사고.)

목표는 **경고·수동 설정 없이**, 각 Remote-SSH 세션이 **당연히 "지금 내가 VS Code를
돌리는 그 PC"** 를 제어하는 것. web·screen·voice **셋 다 동일 규칙**.

## 목표 / 비목표 / 반목표

**목표**
- web·screen·voice 모두 현재 세션의 **클라이언트 PC**로 라우팅.
- 사용자 관점 **무경고·무추가설정**.
- 같은 계정으로 **여러 PC 동시 접속해도 충돌 없음**.

**비목표**
- 로컬(비 Remote-SSH) 사용 방식 변경(기존 loopback 그대로).
- 탐지/경고 UI(사용자가 명시적으로 거부 — "당연히 내 PC").

**반목표(이렇게 되면 실패)**
- 엉뚱한 PC를 **조용히** 조작(현 버그) 재발.
- 기본값으로 인한 **silent misrouting** — 앵커가 없으면 **조용히 딴 데로 가느니 눈에 보이게 실패**해야 한다.

## 제약

- 같은 계정 → `~/.claude` 공유. 세션 구분은 **`SSH_CONNECTION`**(검증: 각 세션/Claude
  프로세스가 자기 연결의 클라이언트 IP를 보유)만 가능.
- Claude Code MCP config는 `${VAR}` / `${VAR:-default}` 확장만 지원. **unset이면 literal
  URL(깨짐)+경고** → 기본값을 두지 않는 쪽이 안전(가시적 실패).
- 비(非)루프백 바인딩은 **토큰 게이트 필수**(web/screen 이미 지원 — `authtoken`).
- 서버↔클라 도달성 필요(LAN/Tailscale). 검증: 서버(11.25)→클라(192.168.11.2) ping OK.

## 검토한 접근 (Approaches)

- **A. PC별 고정 포트 + 세션이 자기 것 자동 선택** — 터널 유지, "내 포트 선택" 로직이
  한 겹 더. 덜 깔끔. 제외.
- **B. VS Code 확장 채널로 web/screen 중계** — voice(훅 push)를 못 담고, 사용자가
  "web/screen은 MCP 구조로"를 명시 → 제외.
- **C1. (선택) reverse tunnel 제거 + 서버가 세션의 클라 IP로 직접 다이얼** —
  실측으로 전부 검증됨(아래). 가장 안정적(포트 경쟁 자체가 없음), 추가 설정 최소,
  MCP 네이티브. voice도 **같은 앵커**로 통일.

검증 결과(C1): `AGLINK_CLIENT_IP=${SSH_CONNECTION%% *}` → `192.168.11.2` 정확 도출 ·
Claude 프로세스가 SSH_CONNECTION 연결별 보유 · MCP `${VAR}` 확장 지원 · 서버→클라 ping OK ·
screen 은 `serve --addr` 로 인터페이스 바인딩 이미 가능.

## 설계 (C1)

핵심: **리버스 터널을 없애고, 각 PC의 aglink 데몬을 그 PC의 접속 인터페이스에
토큰과 함께 열어, 서버(원격 Claude)가 세션의 `SSH_CONNECTION` 클라이언트 IP로 직접
호출한다.** 포트를 공유하지 않으므로 충돌이 원천적으로 없다.

1. **클라이언트 데몬 바인딩(인터페이스 + 토큰)**
   - screen: `serve --addr <iface>:48220` (이미 지원). web: `127.0.0.1` 고정을
     인터페이스 바인딩 옵션으로 확장(작은 변경). 둘 다 **토큰 필수**.
   - 바인딩 대상은 "그 PC가 서버에서 도달되는 주소"(LAN 192.168.11.x / Tailscale 100.64.x).
     가능하면 해당 인터페이스로만(0.0.0.0 지양) + 토큰.

2. **원격 앵커 주입**
   - 원격 로그인 환경에서 `AGLINK_CLIENT_IP=${SSH_CONNECTION%% *}` 를 export하여
     Claude 프로세스가 상속하게 한다(상속 경로 검증됨).
   - 주입 위치는 builder가 확정(후보: 로그인 셸 프로파일 / sshd `SetEnv`+`AcceptEnv` /
     aglink 설치 스크립트). 멀티 OS·멀티 PC 고려.

3. **MCP 등록(공유 `~/.claude`, env 파라미터화)**
   - `aglink-web-remote`  → `url: http://${AGLINK_CLIENT_IP}:48219/mcp` (+ 토큰 헤더)
   - `aglink-screen-remote`→ `url: http://${AGLINK_CLIENT_IP}:48220/mcp` (+ 토큰 헤더)
   - **기본값 금지**(`${VAR:-...}` 쓰지 않음) → 앵커 없으면 가시적 실패(반목표 방지).

4. **voice (같은 앵커, VS Code 연관 부분만 별도)**
   - 원격 `~/.claude`에 Stop 훅 설치(세션용). 훅은 `http://${AGLINK_CLIENT_IP}:48231/stop`
     로 POST → 클라이언트의 aglink-voice 확장이 로컬에서 재생.
   - 확장(클라)이 48231을 인터페이스+토큰으로 열고, 원격 훅 설치를 관리.
   - "voice가 VS Code 연관" = 훅 설치/재생이 확장 책임. 라우팅 앵커는 web/screen과 동일.

5. **리버스 터널 정리**
   - `aglink-always-on`의 `-R 48219/48220` 터널은 제거하거나 로컬 전용으로 축소.
     (더 이상 서버 공유 포트에 의존하지 않음.)

## builder에게 남기는 것

- **web 인터페이스 바인딩 옵션**(+토큰 강제) 추가. screen은 `--addr` 사용. voice 확장
  48231 인터페이스 바인딩 + 토큰.
- **`AGLINK_CLIENT_IP` 주입 지점 확정** (로그인 셸/sshd/설치 스크립트 중) — 여러 PC·OS에서
  Claude 프로세스까지 확실히 상속되도록. 실측 포함.
- **MCP 등록을 `${AGLINK_CLIENT_IP}` url 형태로** 바꾸는 설치/마이그레이션 단계.
- **방화벽**: 서버→클라 48219/48220/48231 도달(인터페이스 바인딩 전제) 확인.
- **멀티클라이언트 동시 접속 실측**(집+회사 동시) — 각 세션이 자기 IP로 라우팅되는지.
- **보안 검토**: 비루프백 노출 범위를 꼭 필요한 인터페이스(LAN/Tailscale)로 한정 + 토큰.
  공개/신뢰 경계 밖으로 새지 않도록.
- (선택) 앵커 없음/도달 실패 시 **사람이 알아볼 수 있는 메시지**(조용한 오작동 금지).

## 적용 범위 주의

이 저장소는 여러 세션·여러 PC가 동시에 만진다(CLAUDE.md). 구현은 main에서, 다른
세션의 미커밋 작업과 섞이지 않게 진행. 터널/바인딩/토큰은 운영 중 장애를 낼 수 있으니
단계적 적용 + 롤백 지점 확보.
